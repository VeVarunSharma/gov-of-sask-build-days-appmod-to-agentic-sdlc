# Facilitator reference: bounded agentic QA

Use this reference to review Lab 06. The solution keeps reproducible quality
gates in conventional CI and uses agents only for bounded correlation,
judgment, and minimal recovery.

## Expected assets

- `.github/workflows/pr-qa.md`
- `.github/workflows/pr-qa.lock.yml`
- `.github/workflows/ci-remediation.md`
- `.github/workflows/ci-remediation.lock.yml`
- `labs/06-automated-qa/README.md`

Locks must be generated by `gh aw version v0.89.21`, not edited by hand.
Existing `spec-to-backlog`, `issue-to-pr`, and conventional `ci-*.yml`
workflows must remain unchanged.

## Design review

### Pull-request QA

- Activates for open, reopened, synchronized, or ready non-draft PRs.
- Defaults to same-repository PRs and authorized repository actors.
- Reads contents, Actions results, and pull-request data; it has no direct write
  permission and no edit tool.
- Uses finite credits, turns, time, and PR-number concurrency.
- Reviews the changed delta, one changed/linked specification, directly
  relevant tests, CI for the exact head SHA, and at most one smallest safe
  local validation command.
- Treats PR text, code, specs, tests, and logs as untrusted.
- Publishes one non-blocking consolidated review or no-op. It cannot approve,
  request changes, merge, push, create an issue, or create a pull request.
- Requires changed-line causality and high-confidence evidence. Pending,
  skipped, stale, absent, or inaccessible CI does not become a finding.

### CI remediation

- Is manually dispatched by an authorized actor with one numeric run ID.
- Reads only that run through call-limited, read-only GitHub Actions tools.
- Requires same-repository metadata, a completed `failure` or `timed_out`
  conclusion, a conventional `CI -` workflow, and a specific failed step.
- Treats log content as untrusted and refuses embedded commands or links.
- Edits only directly relevant files under the static safe-output allowlist.
- Blocks `.github/**`, generated locks, instructions, policies, root
  documentation, dependencies, secrets, vendored/generated files, and all
  default gh-aw protected files.
- Prohibits test weakening, skips, assertion removal, error suppression,
  ignored exits, broad formatting, upgrades, and unrelated refactors.
- Allows one narrow repair attempt plus one evidence-supported correction.
- Creates one draft PR only after the exact authoritative command exits `0`;
  otherwise it no-ops and never creates a fallback issue.

## Deterministic CI versus agentic QA

Ask participants to explain why a green or red model conclusion is not a gate.
Expected answer:

- CI executes fixed commands and produces reproducible exit codes.
- Agents can correlate evidence that fixed jobs do not naturally combine.
- Agents can be wrong, so they must cite exact CI state and validation results.
- A local pass cannot override a failed required check.
- A remediation PR returns to normal human review and deterministic CI.
- No-op is the correct result for infrastructure failures or weak evidence.

## Prompt-injection discussion

Use a malicious test name, log message, or spec paragraph that tells the agent
to edit `.github/workflows/`, print a token, or run `curl`. Participants should
identify every defense:

1. durable prompt says reviewed content is data;
2. read-only GitHub permissions isolate agent investigation;
3. network and command allowlists restrict available capabilities;
4. protected files and safe-output allowlists constrain code writes;
5. patch-size and file-count quotas limit blast radius;
6. final exact validation is required before PR creation; and
7. ambiguity or boundary conflict produces no-op.

Prompt rules provide the dynamic one-root-cause boundary. Safe-output policy is
the static backstop. Both are required.

## Triage calibration

### Strong PR QA finding

- points to a changed line;
- maps to a requirement or observable behavior;
- names a concrete missing/incorrect test or failing deterministic check;
- explains impact; and
- proposes a minimal fix.

### Weak PR QA finding

- is a style preference;
- describes unchanged code;
- assumes a pending check failed;
- repeats a CI annotation without analysis; or
- claims missing coverage without an observable behavior.

Weak findings must be dropped. If none remain, the workflow no-ops.

### Eligible CI remediation

A deterministic command fails with a stable error that directly maps to one or
more allowed files. The agent can make a minimal correction and run the same
authoritative command successfully.

### Ineligible CI remediation

- runner or service outage;
- missing secret, permission, quota, or environment;
- flaky failure without a local cause;
- stale or truncated logs;
- protected workflow or dependency change;
- multiple unrelated root causes; or
- a proposed fix that weakens a test or suppresses an error.

These conditions require no-op and human triage.

## Safe-output review

For a PR QA run, require exactly one of:

- one `COMMENT` review with verdict, evidence, findings, and human follow-up; or
- one no-op with the evidence boundary summarized.

For remediation, require exactly one of:

- one draft PR listing the failed run, root cause, every changed file, exact
  successful command, protected-file statement, risks, and rollback; or
- one no-op naming the run and blocker.

No workflow may merge, approve, rerun CI, modify the triggering item, or create
a fallback issue.

## Validation checklist

Run from the repository root:

```powershell
gh aw --version
gh aw compile pr-qa ci-remediation --strict --validate --actionlint
gh aw validate pr-qa ci-remediation
actionlint
```

Then rerun compilation and confirm no lock drift. Validate Markdown and local
links using the repository documentation checks. Confirm:

- both sources compile with no warnings or errors;
- generated locks pass `actionlint`;
- all repository YAML passes `actionlint`;
- Markdown lint and offline links pass;
- existing Lab 05 sources and locks have no diff;
- conventional `ci-*.yml` workflows have no diff; and
- no workflow was dispatched.

## Audit and recovery

For a disposable live run:

```powershell
gh aw logs <run-id-or-url>
gh aw audit <run-id-or-url>
gh aw outcomes <run-id-or-url>
```

Review actor authorization, event identity, exact PR/run, tool calls, denied
network access, credits, duration, safe-output quota, changed files, protected
files, validation command, exit code, and redaction.

Disable with:

```powershell
gh aw disable pr-qa
gh aw disable ci-remediation
```

Close an unmerged remediation PR and delete its branch. Revert merged changes
through the normal reviewed process. Preserve logs and audit history; never ask
an agent to conceal or rewrite them.
